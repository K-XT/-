## 三、状态机

学生端页面状态与活动阶段是两条线：页面状态由阶段驱动，阶段由 GM 控制。

```
identity → prologue → brief → wall ⇄ confirm → result ⇄ profile
                                                  ↓（阶段切换）
                              vote（vote1 / vote2） → reveal → ending
```

| 页面状态 | 入口条件 | 出口 |
| --- | --- | --- |
| identity | 无有效凭证 | 提交凭证后按阶段与归属分流 |
| prologue / brief / wall / confirm / result / profile | 选角阶段 | 同前 |
| vote | 阶段为 vote1 或 vote2，且已有学生身份 | 提交两票或处置票，可改票 |
| reveal | 阶段为 reveal | 只读，跟随阶段进入 ending |
| ending | 阶段为 ending | 只读 |

阶段五态：`casting`（选角）→ `vote1`（指认+定性）→ `reveal`（揭晓）→ `vote2`（处置）→ `ending`（结局）。

跟随规则：SSE 推送阶段变化后，学生端自动切页；阶段回到 `casting` 时，已归组者回 `result`，未归组者回 `wall`。切页不依赖学生手动点击，避免现场有人停留在旧页面。

窗口状态（open/closing/locked/makeup）与活动阶段正交，只约束选角写入。

## 五、数据模型

- **学生**：`id`、`no`、`name`、`token`、`roleId`、`version`、`switches`、`updatedAt`。
- **角色**：`id`、`no`、`name`、`title`、`situation`、`hook`、`occupied`、`version`、`capacity=7`。

失败码新增：`phase_closed`（阶段不允许）、`invalid_choice`（选项非法）。

**学生身份：免登录自动分配**

学生端没有任何登录步骤，打开即进入：

1. 浏览器首次打开时生成并保存 `deviceId`（localStorage）。
2. 前端直接 `POST /api/enroll { deviceId }`，服务端从未被分配的身份里取一个，返回该身份的 `token`。
3. 前端保存 `token`，后续请求与原来完全一致；刷新页面自动恢复，不需重新操作。
4. 页面只显示“正在进入…”；40 个名额用尽返回 `class_full`，显示“名额已分配完，请联系主持人释放”，并提供“重试”。
5. 分配出的是**编号身份**（`01`—`40` 号），不关联真实姓名；大屏与控制台按编号显示。
6. GM 在控制台“未选名单”里对多余或错误分配的身份点“释放登录”，释放后该名额可被新设备领取。
7. `?t=tok-xxxx` 仍然可用，仅用于 GM 自测与旧链接兼容。

**控制台批量操作**

| 操作 | 接口 | 规则 |
| --- | --- | --- |
| 一键补齐 | `/api/admin/autofill` | 只处理未选学生，按当前人数最少的组优先填入，直到无人可填 |
| 一键调剂 | `/api/admin/rebalance` | 只调整已归组学生，从人数最多的组调出、填到人数最少的组，直到任意两组人数差 ≤1 |

两者分工：补齐负责"把人填进空位"，调剂负责"把分布拉平"，组合使用可得到 7/7/7/7/6/6。

调剂的具体规则：每轮取人数最多的组与人数最少的组，若差值 ≥2，则把多数组里序号最大的学生调到少人组，重复直到差值 ≤1。规则确定，可在操作记录里逐条核对。不占用学生改选次数；`locked` 状态下仍可用，属于主持人兜底通道。前端有 6 秒二次确认，按钮上直接显示"确认调剂 N 人"，N 由当前分布模拟得出；已均衡时只提示"当前分布已均衡，无需调剂"，不发起请求。

## 七、控制台会话认证

- 口令默认 `linghao2026`，可用 `GM_PASSCODE` 覆盖；只用于换会话，**不再作为接口凭证**（实测口令直连 401，会话 200）。
- 会话 `issuedAt.expiresAt.nonce.hmac`，HMAC-SHA256，密钥来自 `GM_SECRET`；未设置时启动随机生成，**重启即失效**。
- 有效期默认 8 小时（`GM_SESSION_TTL_MS` 可覆盖），篡改任意一位即拒绝。
- 前端存 `sessionStorage`，401 自动回登录层。

## 八、投票与揭晓（M8/M9）

**投票规则**

- `vote1` 同时投指认票（六选一）与定性票（A/B/C），两票缺一不可提交。
- `vote2` 投处置票（四选一），决定结局。
- 每人每轮一票，开放期间可改票，改票覆盖原记录且不增加投票人数。
- 幂等键去重：网络重试、双击、刷新重投都只落一票；同一幂等键被另一学生使用直接拒绝。
- 非投票阶段（casting/reveal/ending）提交返回 `phase_closed`。
- 选项校验在服务端：不存在的角色、A/B/C 之外的定性票、e1—e4 之外的处置票一律 `invalid_choice`。

**答案保护**

- `bootstrap` 下发的 `voteMeta` 只含题干与选项文本，**不含 `answerRoleId`、`answerKey`、`verdict`**（实测 `leaks_answer=false`）。
- 投票期间 `voteSummaryPublic()` 返回 `hidden=true`，不携带任何分布明细，只给已投人数。
- `/api/reveal` 在进入 `reveal` 之前返回 409，避免提前剧透（实测 `reveal_before=409`）。
- 揭晓后分布转为可见，并带正确答案与结局。

**揭晓内容**

三条谜题答案、责任链、责任链点题、三段主题落点、指认票与定性票分布（正确项高亮）、结局三段文案（三个月后 / 一年后或三年后 / 一句话）。

**结局判定**

处置票最高项对应结局；平票按 `e1→e4` 顺序，即"撤回重做"优先。当前不提供 GM 手动指定结局。

## 九、实时同步与降级

- 正常路径：SSE，500ms 合并推送；推送内容含 `phase`，学生端与大屏据此切视图。
- 降级：连续 3 次失败切 1 秒轮询 `/api/snapshot`，每 60 秒尝试恢复 SSE。
- 大屏横幅区分"正在重新同步"与"已切换为每秒轮询"。

- **角色卡恢复**：未选角返回 null；选角后秘密/任务/时间线/辩护四项均为完整文本；未选角的他人拿不到；角色墙不含任何 `secret`；改选后角色卡跟着换。
- **线索三态**：初始全部 hidden 且不下发名称；发第 1 轮后 L1—L5 public；发第 2 轮后 L6 为 held、他组无 `content` 但可见名称；非持有组交卡被拒，持有组交卡后全场可见；发第 3 轮后 L8 定向且林澈组带交卡提示；进入 confront 自动公开 L8，强制公开幂等。
- **质询配额**：进入质询阶段每组配额 1；记录一次后归零、第二次被拒；非法回答被拒；文字质询入队但不扣配额；重新进入阶段重置配额。
- **静默态**：判定后出现在快照；静默组不能发起质询；同阶段重复判定幂等；换阶段自动解除；同组全场第二次被拒；撤销后标记消失且可重判。
- **设备分配**：首台设备分配成功；同设备重复进入复用原身份；不同设备分到不同身份；40 台用尽后第 41 台返回 `class_full`；控制台可见分配状态；主持人释放名额后可被新设备领取。
- **启动初始化**：模块加载后（未调用 `reset()`）线索状态必须已初始化、快照显示全部未发放；此时发第 1 轮必须返回 5 条。这条是为一个真实缺陷补的回归：`seedClues()` 原先只在 `reset()` 里调用，服务启动后 `clueStates` 为空，发放接口返回 `ok` 但 `released` 为空。

两项留空：

- **大屏可读**：字号用 vh，未在真实投影上验证 5 米可读。
- **动效降级**：时长已压到 1ms，未逐页确认降级后功能完整。

## 十二、明确未实现 / 未验证

1. **中文二维码**：Vision 未解出中文样本，未排除编码问题；实际内容为 ASCII URL，风险局限于"将来往码里放中文"。
2. **会话持久化**：密钥默认进程内随机，重启后 GM 全部掉线；多实例必须固定 `GM_SECRET`。
3. **学生凭证防代选**：固定码可转借，按决策保留。
4. **对账定时器**：`reconcile()` 已实现，服务端未挂 30 秒定时，只能手动重算。
5. **大屏投票/揭晓视图**：已实现四视图切换，未上真实投影验证字号与票条可读性。
6. **投票压测**：自检是顺序模拟，未做 40 人同时投票的真实并发压测。
7. **揭晓稿政治表述**：剧本要求活动前逐字核对；系统只做展示，未内置敏感词校验。
8. **平票处理**：固定 e1 优先，未提供 GM 手动指定结局。
9. **投票明细导出**：服务端保留每人投票明细用于审计，但没有导出或销毁入口。
10. **动效细节**：信纸展开、逐行打字、印章回弹只实现基础版。
11. **调剂的挑选规则**：固定调"多数组序号最大者"，未提供按加入时间或人工指定；如需保护刚归组的学生，后续要加规则开关。
12. **一键调剂的 HTTP 端到端**：本机沙箱当前禁止端口监听（10 个端口全部 EPERM），只验证到存储层与自检，未跑真实 HTTP 请求。

## 十三、关键取舍对比

| 选择 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| Node 原生 http | 零依赖、断网可跑 | 无中间件、路由手写 | 采用 |
| 内存状态 + 快照回滚 | 并发逻辑可读、便于排查 | 重启丢失、无法多实例 | 骨架采用，正式版换持久化 |
| SSE + 轮询降级 | 正常低开销、异常仍可看 | 降级延迟 1 秒 | 采用 |
| HMAC 会话 | 口令不落到每个请求、可过期 | 多实例需固定密钥 | 采用 |
| 纯 JS 二维码 | 零依赖、离线可用 | 仅 V1—V4、M 级 | 采用 |
| 固定学生凭证 | 便于分发 | 可代选 | 采用 |
| 阶段由 GM 控制 | 现场节奏可控、异常可回退 | 依赖 GM 操作 | 采用 |
| 投票期隐藏分布 | 避免从众影响判断 | 现场看不到实时进度（只看人数） | 采用 |
| 结局按最高票 | 与剧本一致、无需人为裁定 | 平票只能按固定顺序 | 采用 |
| 一键调剂（多数组→少人组） | 一次拉平分布、每条可审计 | 会移动学生已选的组 | 采用，加 6 秒二次确认 |

```bash

# 可选：二维码实扫验证（依赖 macOS Vision，环境不稳定时输出 env_unavailable）
node scripts/qr-verify.mjs
```

启动后终端分两段打印地址：

- 本机：`http://localhost:4173/`
- 局域网：`http://<本机局域网IP>:4173/`，并标注网卡名（如 `en0`）

**其他设备必须用局域网地址，不能用 `localhost`。** 学生端、大屏、控制台都一样。

- 学生端：`http://<局域网IP>:4173/`（打开即进入，无登录步骤；自动分配编号身份 01—40 号）
- 大屏：`http://<局域网IP>:4173/screen`
- 控制台：`http://<局域网IP>:4173/admin`，口令 `linghao2026`

**局域网访问排查**（其他设备打不开时按顺序看）：

1. 启动日志里有没有"局域网 http://..."。只显示"本机"或提示"仅本机可访问"，说明绑定了回环地址，用 `npm start` 重起。
2. 手机与电脑是否同一 Wi-Fi，不是访客网络，也不是手机蜂窝网络。
3. 路由器是否开启 AP 隔离 / 客户端隔离（开启时同 Wi-Fi 设备互相不可见）。
4. macOS 防火墙是否放行 `node`（系统设置 → 网络 → 防火墙）。
5. macOS 15+ 是否允许终端访问本地网络（隐私与安全性 → 本地网络）。
6. 是否开着 VPN / 代理（Clash 等会劫持局域网路由，导致其他设备访问不到）。
7. `npm run lan` 会直接判定"只监听在回环地址"还是"已在局域网监听"，后者才需要继续查第 2—6 条。

> `HOST=127.0.0.1 npm start` 仅用于沙箱/受限环境自测，**现场活动不要用**：它只监听回环地址，其他设备一律连不上。

现场流程：控制台切"投票一" → 学生投指认+定性 → 切"揭晓" → 念揭晓稿 → 切"投票二" → 学生投处置 → 切"结局" → 大屏显示结局卡。

### A.2 线索三态与可见性

采用**两层可见性**：L1—L5 全员，L6—L9 定向持有，L8 定向 + 程序强制公开。

| 状态 | 含义 | 学生端 | 大屏 | 控制台 |
| --- | --- | --- | --- | --- |
| `hidden` | 未发放 | 只有灰格编号，无名称与内容 | 不显示 | 待发放 |
| `held` | 定向持有 | 持有组：编号+名称+全文+"交不交由你们组决定"；他组：编号+名称+"第 N 组持有" | 编号+名称+持有组 | 含交卡状态 |
| `public` | 全员 | 编号+名称+全文 | 全文 | 同上 |

**关键修订**：编号与名称对全员公开，只有**内容**受状态控制。理由有两条：编号是推理契约（R2），若编号都不可见，就会出现"没人知道还存在线索"的死锁；剧本书面也是实体卡，大家看得见某组手里有卡。

| 编号 | 名称 | 初始态 | 持有组 | 释放轮次 | 特殊机制 |
| --- | --- | --- | --- | --- | --- |
| L1 | 举报信 | public | — | 第 1 轮 | — |
| L2 | 申报书第 17 页 | public | — | 第 1 轮 | — |
| L3 | 后台数据截图 | public | — | 第 1 轮 | — |
| L4 | 提交记录与承诺书 | public | — | 第 1 轮 | — |
| L5 | 获奖公示 | public | — | 第 1 轮 | — |
| L6 | 聊天记录 | held | 周予组 | 第 2 轮 | 自愿公开 |
| L7 | Word 修订记录 | held | 苏晚组 | 第 2 轮 | 自愿公开 |
| L8 | Git 删除记录 | held | 林澈组 | 第 3 轮 | **程序强制公开** |
| L9 | 工作日志与草稿 | held | 沈知白组 | 第 3 轮 | 自愿公开 |

持有组由 `roleId → 组号` 推导，不需要额外配置；该角色所在组即持有组。

### A.3 L8 强制公开的程序化落法

- **触发**：阶段进入 `confront` 时由服务端自动执行，`clueId=L8` 幂等，只执行一次。
- **呈现**：大屏出现"核查小组调取记录"文书卡（与举报信同一视觉体系），正文为"后台操作日志 · Git 删除记录"，**不出现 GM 口述式文案**。
- **记录**：`releasedBy = 'procedure'`、`releasedAt`，文案锁定，不允许 GM 改写。
- **兜底**：控制台保留"重新投影 L8"，幂等，不重复计数。
- **理由**：公开动作由程序完成，GM 不承担"我看不下去了"的角色，这本身就是"制度可以强制、个人无法强制"的演示。

### A.4 质询双通道

| 通道 | 形态 | 系统职责 |
| --- | --- | --- |
| 主通道 | 举手 → GM 点名 → 口头质问 → 30″ 回答 | 只做计时与记录，**不提供语音、不提供文字回答输入** |
| 辅通道 | 学生端提交文字质询（可匿名） | 队列 + GM 挑选 3—5 条上屏，其余不上屏 |

- 回答类型只有三种：`yes` / `no` / `decline`（是／不是／我不回答），由 GM 记录，用于留痕与判罚依据。
- 辅通道每人每轮限 1 条；匿名**只对其他学生生效**，控制台可见来源（否则无法约束刷屏）。
- GM 只挑不全部转述，避免变成念稿大会。

### A.5 静默态（替代"公开承认编造"）

| 层 | 处理 |
| --- | --- |
| 大屏 | 该组卡片转灰，标"本轮静默"，持续到本轮结束，下一阶段自动恢复 |
| 文案 | 只写"本轮静默"，禁用"编造""违规""作弊" |
| 控制台 | 记录组号、原因、时间、判定人、第几次、是否撤销 |
| 揭晓 | 以卷宗口径呈现"本轮静默共 N 次"，不点名、不解释 |

行为约束：静默组**不能发起质询**，但**仍须回答**被质询（三选一），**仍可投票**（投票是书面，不是发言）。

心理保护（默认开启）：同一组全场静默最多 1 次；第 2 次转为 GM 私下提醒，不进入大屏。
