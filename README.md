# 零号提交 · 互动选角与推理活动系统

线下团日活动用的三端网页系统：40 人分 6 组，选角色、读线索、质询对质、三票表决、揭晓结局。零依赖，一条命令启动。

## 1. 项目是什么

一起虚构的学术诚信事件：某学院"星火小组"的获奖作品被匿名举报"代码抄袭 + 用户数据编造"。六名当事人各自只做了一小步，没有一个人是坏人。参与者用 45 分钟还原责任链，并在三种票上作出判断。

系统负责的是**流程承载**：选角、线索发放、质询、投票、揭晓、结局，以及现场控制台的节奏推进与留痕。

## 2. 当前形态（重要）

- **学生端完全没有登录**：打开页面直接进入，后台按设备自动分配一个编号身份（`01 号`—`40 号`）。同一设备刷新后复用原身份，不重复占号。
- **不显示真实姓名**：名单已改为编号代号，大屏与控制台按编号显示。角色卡、投票、归组都按设备绑定。
- **控制台需要口令**：默认 `linghao2026`，登录后签发 8 小时会话。这是唯一保留的认证。

## 3. 环境与启动

要求：Node.js >= 22，无需安装任何依赖（无 npm 包、无构建步骤）。

```bash
npm start            # 启动服务，默认 4173 端口
npm run lan          # 局域网自检：网卡、端口连通性、排查清单
npm run selfcheck    # 26 项验收自检
```

启动后终端会打印：

```
  监听     0.0.0.0:4173
  本机     http://localhost:4173/
  局域网   http://172.31.78.156:4173/   (en0)
  大屏     http://172.31.78.156:4173/screen
  控制台   http://172.31.78.156:4173/admin
  GM 口令  linghao2026（登录后签发 8 小时会话）
```

**其他设备必须用"局域网"那一行，不能用 `localhost`。**

## 4. 三个入口

| 端 | 地址 | 用途 |
| --- | --- | --- |
| 学生端 | `http://<局域网IP>:4173/` | 选角、线索册、质询台、投票、揭晓、角色卡 |
| 大屏 | `http://<局域网IP>:4173/screen` | 只读：六组进度、线索公示、陈述/质询计时、票数、结局 |
| 控制台 | `http://<局域网IP>:4173/admin` | 口令登录：阶段推进、线索发放、静默、调剂、补齐、导出 |

## 5. 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `4173` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址。**改成 `127.0.0.1` 会只允许本机访问** |
| `GM_PASSCODE` | `linghao2026` | 控制台口令 |
| `GM_SESSION_TTL_MS` | 8 小时 | 会话有效期 |
| `GM_SECRET` | 启动时随机 | 会话签名密钥。不设置则重启后所有会话失效；多实例部署必须固定 |

## 7. 活动流程（8 阶段）

阶段由控制台推进，学生端与大屏通过 SSE 自动跟随，不需要学生手动切页。

| 阶段 | 时长 | 内容 | 线索 |
| --- | --- | --- | --- |
| `casting` 选角 | 4′ | 发角色卡五项、读本、推发言人 | 发第 1 轮 L1—L5 |
| `statement` 陈述 | 6′ | 六组按 01→06 顺序陈述，每组 1 分钟 | — |
| `interrogate` 质询 | 7′ | 口头为主、文字为辅；每组本轮 1 次机会 | 质询结束后发第 2 轮 L6—L7 |
| `confront` 对质 | 7′ | 三组互质；进入即自动强制公开 L8 | 发第 3 轮 L8—L9 |
| `vote1` 投票一 | 6′ | 指认票（六选一）+ 定性票（A/B/C） | — |
| `reveal` 揭晓 | 6′ | 谜题答案、责任链、票数分布、正确答案 | — |
| `vote2` 处置 | 3′ | 处置票（四选一），决定结局 | — |
| `ending` 结局 | — | 按最高票公布四种结局之一 | — |

## 8. 角色与线索

**六个角色**（每组扮演一个，组内共享）：

| 角色 | 身份 | 卡片背面的钩子 |
| --- | --- | --- |
| 林澈 | 队长 | 你删过一行注释。 |
| 周予 | 技术 | 那行注释，你确定写过。 |
| 陈默 | 数据 | 那个数字，是你一条一条填的。 |
| 苏晚 | 答辩 | 修订模式，你没关。 |
| 顾承 | 学长 | 你说过「别提我名字」。 |
| 沈知白 | 科创部 | 信是你写的，第三版。 |

**九张线索**分两层可见性：

| 编号 | 名称 | 可见性 | 持有组 | 轮次 |
| --- | --- | --- | --- | --- |
| L1 | 举报信 | 全员 | — | 1 |
| L2 | 申报书第 17 页 | 全员 | — | 1 |
| L3 | 后台数据截图 | 全员 | — | 1 |
| L4 | 提交记录与承诺书 | 全员 | — | 1 |
| L5 | 获奖公示 | 全员 | — | 1 |
| L6 | 聊天记录 | 定向 | 周予组 | 2 |
| L7 | Word 修订记录 | 定向 | 苏晚组 | 2 |
| L8 | Git 删除记录 | 定向 + **强制公开** | 林澈组 | 3 |
| L9 | 工作日志与草稿 | 定向 | 沈知白组 | 3 |

定向卡由持有组自行决定是否公开；L8 在林澈组手里，靠他自愿公开不可能，所以进入 `confront` 时由服务端以"核查小组调取记录"的名义强制公开，并幂等。

## 9. 投票与结局

| 票 | 选项 | 正确答案 |
| --- | --- | --- |
| 指认票 | 六个角色选一 | 林澈 |
| 定性票 | A 能力不足 / B 监管缺位 / C 主动掩盖 | C |
| 处置票 | e1 撤回重做 / e2 推出替罪 / e3 集体沉默 / e4 补真数据 | 最高票决定结局 |

投票期间**不公布分布**，只显示已投人数；进入 `reveal` 后才公开票数与正确答案。

## 10. 三端各自能做什么

**学生端（M0—M11）**：序章 → 案件简报 → 角色墙（3D 翻转、满员置灰）→ 确认层 → 归组印章 → 角色卡（五项）→ 线索册（定向卡可交卡）→ 质询台（配额、匿名文字提问）→ 两轮投票 → 揭晓 → 结局。

**大屏**：8 类视图切换；六组进度条与姓名滚动；线索公示（公开全文 / 定向只显示持有组）；L8 调取记录文书卡；陈述 60″ 与质询 30″ 计时；静默组灰卡；票数分布与结局。

**控制台**：窗口四态与阶段八态（均二次确认）；三档线索发放、重新投影 L8、缺卡预警；陈述推进、发言人录入；质询记录与文字队列上屏；静默判定/撤销；手动调剂、一键补齐、一键调剂；计数对账；操作记录导出 JSON。

## 12. 数据与状态

所有状态在内存里，**重启即清空**。40 个编号身份按设备分配；设备首次打开取一个未占用的号，刷新复用。名额用尽时学生端显示"名额已分配完，请联系主持人释放"，在控制台"未选名单"点"释放登录"即可回收。

## 13. 验收与自检

```bash
npm run selfcheck
```

当前 **26 项：绿 24 / 黄 2 / 红 0**。覆盖：容量数学、满员引导、幂等、改选守恒、并发抢位、计数一致、不满不标红、窗口锁定、断网重试、GM 兜底、会话签名、二维码结构、SSE 降级、投票门控/计数/幂等、揭晓与结局、一键调剂、角色卡恢复、线索三态、质询配额、静默态、设备分配、启动初始化。

两项黄是**已知未验证**，不是通过：

- 大屏可读性：字号用 vh，未在真实投影上验证 5 米可读。
- 动效降级：时长已压到 1ms，未逐页确认降级后功能完整。

## 14. 已知限制

1. 无持久化：重启后归组、投票、线索全部清空。
2. 会话密钥默认随机：重启后 GM 需重新登录；多实例必须设 `GM_SECRET`。
3. 学生身份是匿名的：系统里没有真实姓名，现场核对只能靠线下登记。
4. 40 人并发未做真实压测，自检是顺序模拟。
5. 中文二维码未通过 Vision 验证；实际内容是 ASCII 链接。
6. 投票明细、环节日志可导出，但没有销毁入口。
7. 一键调剂固定调"多数组序号最大者"，没有保护刚归组的开关。

## 15. 常见问题

**手机打不开页面**
先运行 `npm run lan`。它直接判定"只监听回环"还是"已在局域网监听"。若已监听，依次查：同一 Wi-Fi、路由器 AP 隔离、macOS 防火墙、macOS 15+ 本地网络权限、VPN/代理。

**学生打开显示"名额已分配完"**
40 个号都被占用。控制台 → 未选名单 → 对多余身份点"释放登录"，学生端点"重试"。

**端口被占用**
启动时会提示 `EADDRINUSE`。用 `PORT=4180 npm start`，或 `lsof -ti tcp:4173 | xargs kill` 清掉旧进程。

**线索点了发放但没反应**
已在早期版本修复：`seedClues()` 原先只在 `reset()` 里调用，服务启动后线索状态为空，接口返回成功但 `released` 为空。现在有 `check_boot_init` 回归断言与 `clue_not_initialized` 错误码。若仍出现，重启服务。

**大屏与人端数据延迟**
正常走 SSE；连续失败 3 次会切 1 秒轮询，大屏顶部会出现"已切换为每秒轮询"。

## 16. 设计取舍

- **零依赖**：Node 原生 http + 浏览器原生 API，断网也能跑，现场不需要装包。
- **阶段驱动**：页面切换只由服务端阶段推进，避免 40 人各自停在不同的页面。
- **SSE + 轮询降级**：正常 500ms 合并推送；网络不稳时自动降级，活动不中断。
- **匿名编号而非实名**：不登录意味着无法知道"第 3 号是谁"，但换来零操作成本；归组、投票、角色卡都不依赖实名。
- **内存态**：换来并发逻辑简单可读、现场易排查；代价是不能多实例、不能重启保留。
